# 解説図の仕様と保守

図は解説本文の `detail` に `diagram` コードフェンスで保存する。既存のID、customストレージ、個人データversion=1、エクスポート形式は変更しない。別画像サーバーや独立した図IDの管理を増やさず、説明と図を同時に保存・再読込する。

## 表現の選択

| mode | 用途 | 必須データ | 上限 |
|---|---|---|---|
| flow / memory | 旧形式の手順・項目配置 | rows: 文字列配列 | 12行、各80文字 |
| table | 宣言・値・状態・方向の比較 | columns, rows: セル配列の配列 | 4列×12行、列名50文字・セル200文字 |
| bits | ビット番号とフィールドの幅 | fields: {label,bits,value?}[] | 16欄、合計64ビット、label40文字、value80文字 |
| layout | 量の比例、開始位置、領域と境界 | start, unit, segments: {label,size}[], marks?: {offset,label}[] | 12領域、8境界、start≤2^40、size≤2^36 |
| map | 場所・値・参照先・複数主体 | columns, nodes: {id,label,column,row}[], edges: {from,to,label}[] | 3列×6行、18ノード、24矢印 |
| sequence | 主体ごとの処理と受け渡しの順 | lanes, steps: {from,to,label}[] | 4主体・12手順 |

共通のmode/titleが必須。titleは200文字、任意noteは600文字まで。すべての文字列は空白のみ不可。数値は有限な安全整数。未定義のプロパティは拒否する。mapのIDは英小文字・数字・ハイフンで40文字以内。位置とIDは重複不可、矢印は異なる既存IDを結ぶ。ノードのlabelは120文字、矢印は24文字。列・主体名は50文字、sequenceのlabelは120文字。layoutのunitは20文字、領域labelは160文字、境界labelは120文字。offsetはstartからの差で、全領域長以内。

```diagram
{"mode":"bits","title":"Sv32の仮想アドレス","fields":[{"label":"VPN[1]","bits":10},{"label":"VPN[0]","bits":10},{"label":"offset","bits":12}]}
```

上からビット31〜22、21〜12、11〜0に対応する。小さいビット欄は文字のために拡大するので、完全な等縮尺ではない。layoutの帯は量に比例するが極小領域は最低1px。境界は領域として描かない。アドレスは16進数の包含範囲（末尾はstart+size−1）、marksは境界の位置を別表示する。tarの例ではRAM番地ではなくファイル先頭からのオフセットであることを本文で明記する。

map/sequenceは固定構造のSVG、bits/layout/tableは意味を持つDOMで描画する。ラベルの長さと改行から高さを決める。通常幅で関係が見渡せるようmapをコンパクトに配置し、狭幅では文字を縮小しすぎず図の内側で横スクロールする。スクロール領域はキーボードでフォーカスできる。全図に「図を文章で読む」を用意し、図前後の文章にも重要な説明を残す。

## 共通図への案内

同じ仕組みを扱う既存の解説に `[[context|図：コンテキスト切り替え]]` のようにリンクする。本文にその図のどこを見るかを添える。「図：」で始まるリンクは、教材ポップアップでは詳しい説明を展開して図へ移動し、辞書では図へスクロールする。

`prerequisites`は理解の順序なので非循環のまま。明示リンクは関連項目へ戻ることも許可し、参照先の存在を検査する。ナビゲーション履歴の24件上限と既存の戻る操作は維持する。個人編集で共通図の本文が変わる場合もその編集を優先し、自動上書きしない。

## 生成・保存の検証

新しい生成要求は `diagramDecision: {rating: "A"|"B"|"C", reason: string, existingTerm: string}` を要求する。Aは図または確認可能な共通図を必要とし、Bは理由があれば省略可能、Cは図なし。枚数のノルマは設けない。既存図はknown.hasDiagramで提示し、参照語の存在を照合したうえでサービスワーカーが安定したIDリンクを追加する。生成中に共有先が変更された場合も保存前に再検査する。

- 生成応答・前提項目・scopeNoteの図を検証する。表のJSON配列 `[[` を本文リンク記法と混同しない。
- 手動保存、importする新規/初期項目の編集、ビルドで同じ検査を使う。importの競合は従来どおり既存の個人データを優先し、上書きしない。
- 閉じていないフェンス、不正なJSON、範囲外のサイズ・参照・プロパティを拒否する。保存失敗でも編集欄を残し、図番号と行番号を表示する。
- 過去に保存済みの不正図は、原文と周囲の文章を表示する。読み込み時に削除・移行・書換えをしない。
- HTML/SVG/JavaScript/URLをAIから実行可能な描画定義として受け付けない。ラベルはtextContentで挿入する。描画CSS・属性・構造は拡張側で固定する。

旧API応答のdiagramDecisionなしは互換のため受け付けるが、新リクエストのJSONスキーマでは必須。過去のデータをこれだけのために再生成しない。

## 更新と検証

`npm run build`でextension/data.js、chapter-text.js、native/ai.js、native/diagram.jsを生成する。補助プログラムの配布にもdiagram.jsを含める。既にインストールされた補助プログラムはsetup-helper.cmdで更新し、拡張もChromeで再読込する。認証方式・ホストID・モデル設定は変更していない。

`npm test`、`node scripts/check-explanation-review.cjs`、`node tests/quality-browser.cjs`を使う。ブラウザテストは一時Chromeプロファイルで実行する。AI応答だけ模擬化し、実際の保存・import・再読込・描画を通す。実アカウントや個人辞書は使わない。

監査前の一度限りの一括生成・補正スクリプト4本は監査対応表がある場合に停止する。古い3図や本文を再適用して監査反映を戻さないためである。追加修正はdata/*.jsonの必要箇所を個別に編集して検証する。

B追加改善：2列表は最小幅を外して等幅の列にし、狭い画面でも両側を同時に比較できます。3列以上の表は従来の内部スクロールを維持します。新しい図形式や保存形式は追加していません。
